Adversarial defence for ML-based IDS

Never the same
model twice.

Apollon answers every request with a classifier drawn by Thompson sampling. Attackers cannot learn a boundary that keeps moving. Detection stays accurate.

Get started Read the paper ↗
  • Published in Computers & Security, vol. 136, 2024
  • Five classifiers per cluster, one drawn per request
  • Drop-in scikit-learn estimator and command line
WhereBehind any flow-based IDS
What it stopsBlack-box evasion
CostOne model per request

The problem

A fixed model is a target.

ZOO and HopSkipJump query an IDS, estimate where its decision boundary lies and push an attack just across it. That only works if the same model answers every query.

Attackers probe

Thousands of queries, each a slightly modified attack flow.

They map the boundary

Every answer refines their estimate of where benign begins.

They step across

The smallest change that flips the verdict becomes the evasion.

Illustration of the mechanism. Measured results are in the paper.

How it works

Sample, don't choose.

Every classifier keeps a Beta posterior of how often it is right. Each request draws one value per classifier; the highest draw answers. Good classifiers answer most requests, but no answer is predictable.

01

Cluster

K-Means splits traffic; every classifier is trained per cluster.

02

Draw

One Beta draw per classifier; the highest answers this request.

03

Learn

Analyst feedback updates the posteriors online.

Thompson samplerInteractive
Draw a request to start.

Use it

From CSV to verdict.

A scikit-learn estimator for your pipelines and a command line for experiments. Four commands take a CIC dataset from raw CSV files to an adversarial evaluation.

quickstart.py
from apollon import ApollonMAB
from apollon.data import prepare

data = prepare("cic-ids2017", ["data/CIC-IDS2017/"])
model = ApollonMAB(random_state=0)
model.fit(data.X_train, data.y_train)

# one Thompson draw per request
pred, arms = model.predict(data.X_test, return_arms=True)

# analyst feedback updates the posteriors
model.update(X_reviewed, y_reviewed)

Questions.

      

        
Does Apollon slow detection down?
          
No more than a single model: each request costs one cluster assignment, one Beta
          draw per classifier and one classifier evaluation. Training fits every classifier
          on every cluster.

        
Can I use my own classifiers?
          
Yes. Any scikit-learn classifier with predict_proba can be passed in
          ApollonMAB(arms=[...]); the paper's pool is RF, DT, NB, LR and MLP.

        
Does it need labels at run time?
          
No. Labels are needed to train. Afterwards, analyst feedback is optional: when it
          arrives, update moves the posteriors of the classifiers that answered.

        
Which attacks were evaluated?
          
ZOO and HopSkipJump, targeted towards the benign class, with functional features
          kept fixed, both querying Apollon directly and transferring from a surrogate.

        
Can analysts audit a randomised answer?
          
Predictions are reproducible with a seed, and every answer reports which
          classifier produced it (return_arms=True), so alerts stay auditable.

        
How do I cite Apollon?
          
Cite the article in Computers & Security 136, 103546 (2024). BibTeX, APA and
          IEEE formats are on the citation page.
